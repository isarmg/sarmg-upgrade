# 10. 阅读顺序与术语

先阅读 CLI 的计划、升级、检查和恢复入口，再沿 `mod.rs` 中的 `preflight`、`apply_inner`、`recover` 与对应故障测试继续阅读。接着查看 `snapshot` 的安全打开、资源清单、所有权和恢复，`native_release` 的完整发行根目录、`current` 与修复，以及 `execution` 的属主和固定文件描述符执行。

| 术语 | 在工具中的含义 |
|---|---|
| `ReleaseIdentity` | 真实软件、完整源码提交、目标平台和状态合同摘要 |
| `SchemaIdentity` | 实际持久结构身份；独立于软件版本 |
| `state_paths` | 产品全部不可重建的持久输入路径 |
| `artifact` | 本工具受签名的交付方式与物理发行根目录定义 |
| 待恢复门 | 阻止正常启动；存在本身不授权写入 |
| 维护锁 | 工具排他、运行时共享的运行权协议 |
| 资源清单 | 每项路径、类型、模式、长度和摘要 |
| 所有权 | 每项实际 UID/GID |
| `backup-complete` | 全部快照已验证可用于恢复 |
| 操作意图 | 在有副作用操作之前持久记录意图 |
| `current` | 唯一受控绝对选择链接，指向已声明的物理版本发行根目录 |
| `--allow-data-loss` | 明确接受丢弃备份之后可能发生的业务写入 |
| 业务就绪 | 实际程序、PID、UID、摘要与正确产品的业务检查同时通过 |

应能解释为何停服后还要排他锁，为什么恢复程序必须同时恢复配置和数据，为什么启动超时不能默认丢弃写入，以及为何软件版增长不要求数据标签增长。
