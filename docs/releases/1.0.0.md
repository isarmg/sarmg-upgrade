# xssc 1.0.0

此版本将当前实现整理为 1.0.0 发布基线，正式标签为 `v1.0.0`，`main` 从一个初始提交开始。

项目、软件包、命令、服务、安装产物及移动端标识按统一四字母命名表更新；最后一位 `s` 表示服务端，`c` 表示客户端。当前项目名为 `xssc`。本项目的公共支撑为单体客户端 Rust 包 `xcsc`。

产品依赖固定到新的 1.0.0 基础库和提交。协议版本、数据库结构版本及第三方工具版本独立管理，不随软件发布版本重置。

更新工具前确认当前计划及恢复记录，校验新工具签名和制品；实际产品升级按离线升级文档执行停服、备份和恢复。旧数据目录、系统服务及移动应用标识不会自动迁移。基础库项目通过依赖方式接入，无需单独安装后台服务。

参见[项目 README](../../README.md)。

## 内部版本从初始值开始

本次重建的软件发行号为 `1.0.0`。项目自定义的配置、持久状态、数据库结构、API、通信协议、ABI 和发行清单均以 `v1` 或数值 `1` 作为初始标识；使用语义版本作为身份的配置采用 `1.0.0`。第三方依赖、外部软件 API 和字体上游版本遵循其实际版本要求。

升级工具与目标产品的版本和合同按计划独立核验。旧版配置或数据库不直接覆盖新目录；先导出数据并保留备份，再按目标产品的平台部署文档处理。xssc 自身没有配对流程。

## 单体公共支撑与当前工作区更改

本项目的公共能力只来自一个 `xcsc` 包，内部模块已物理合并。日志由 `xcsc::log` 提供，移动 FFI/JNI 通过显式特性保持原生布局、符号和释放约定。Cargo 完整提交修订、角色描述与实际锁图同步核对。

升级工具使用同一个 xcsc 包的 `offline-maintenance` 特性。它按服务器已有合同维护数据、执行签名制品升级与恢复，不消费服务端 HTTP 或管理员生命周期实现；它没有常驻服务、管理网页或配对流程。状态锁现在显式解锁，防止并行子进程继承描述符造成已释放的维护锁仍被占用。

本次提交同时纳入工作区已有的代码、界面和文档修改。部署入口与命令以当前[运维文档](../README.md)为准；历史拆分包的验证不代替最终源码的 CI、平台验收和发行资产核对。
