# 服务端版本升级规范

本文件是服务端版本升级的职责、支持范围、流程与验收约束。按用户要求，相关内容只在本仓库维护；被升级项目及共享文档不保留工具名称、专用命令、字段、路径约定或操作说明。

## 1. 独立离线辅助工具

`xssc` 在操作者停止服务端后运行。执行前确认服务及相关持久资源的其他写入进程均已停止；仍在运行、状态未知或停服尚未完成时拒绝执行，不能代替操作者协调停服。

被升级项目不依赖本工具、不识别本工具的会话或内部阶段、不接收本工具专用指令，也不委托本工具执行操作。初始化、当前配置/数据校验、发行身份和就绪诊断保持产品自己的普通接口。本工具可以在离线维护中使用这些接口，但不得为了调用它们在产品中建立专属协议。

安装器、系统服务封装及容器围绕同一发行物工作，不能复制另一套升级实现。公共基础仅提供产品无关的文件安全、状态身份、维护锁和待恢复状态等机制，不管理具体产品或工具阶段。

## 2. 仅从当前基线面向未来版本

支持起点是本轮完成改造后的当前版本。受签名自动切换不提供此前旧版升级、通用历史结构识别或补迁移。本轮删除旧版本专用入口，只支持当前严格合同；任务、指纹和业务事实均由当前产品校验保护。

当前结构相同的程序更新直接严格校验并切换。未来发行确实改变数据结构时，由工具在该次发行中提供从受支持当前结构到目标结构的明确实现；不预先制造虚拟转换，不通过改版本号或指纹冒充转换。

数据身份与软件发布版本分别管理。多个软件版本使用同一数据结构时复用相同数据身份；不得仅因数据标签数字早于软件版本而误判为旧结构。

无法识别、超出范围、已经损坏或缺少明确实现的输入应拒绝并保护原始状态。在线服务端始终只接受自身当前契约，不能因本工具存在而扩大解析范围。

## 3. 权威输入与可信制品

升级所需的产品定义、源/目标结构关系、持久资源清单、完整发行布局和转换实现由本仓库拥有，不从产品软件版本猜测，不要求产品提供专用升级命令。

目标必须匹配平台、架构、完整源码身份、文件摘要和当前数据契约。签名验证使用独立取得的可信密钥身份，不能把制品携带的自报摘要或公钥作为充分信任依据。不得接受任意脚本钩子、任意可执行路径或附加参数。

完整发行根必须作为整体封存、校验和切换；不能以单个程序替换遗漏配置模板、网页资源、必要配套进程和其他发行资源。独立单二进制产品按其完整交付单位处理。

## 4. 明确维护阶段

```text
操作者停止服务端及相关资源写入服务
    → 工具只读确认停服并预检查输入
    → 取得通用独占维护权并复查状态
    → 生成完整可恢复备份
    → 执行本次实际需要的数据处理并严格校验
    → 原子切换目标发行物
    → 有序交接运行权
    → 启动并验证真实业务就绪
    → 记录结果或执行明确的失败恢复
```

每阶段有明确的完成条件、持久意图与中断状态。必须区分尚未修改、修改中断、切换尚未完成、新程序已经启动及新程序可能产生业务写入；不能只保留“升级中/成功”两个状态。

正常运行、只读诊断和独占维护使用同一通用锁及目录身份。锁、权限、文件身份和待恢复门的验证不得因为缩减旧版支持而削弱。root 行政操作与服务 UID 分离；新文件及恢复内容保持正确属主，服务 UID 不能修改封存执行树。

## 5. 数据与完整发行根同时恢复

备份覆盖升级前的当前程序、配置、数据库及必要附属文件、媒体/录像等完整持久资源以及完整发行根。诊断临时副本或未经一致性保障的现场复制不等于可恢复备份。

恢复依据持久记录和实际校验，不因某进程退出就从头重跑。恢复前同样要求操作者先停服。恢复后验证原组资源、权限、程序身份和真实业务就绪，不能以进程存在代替成功。

交接运行权后默认保全可能新增的业务写入；未经明确授权不能恢复旧备份并丢弃新数据。不可逆步骤、损失范围和人工处理要求必须预先明确，恢复损坏或来源不符的备份时应拒绝并保全当前状态。

## 6. 实际验证与记录归属

测试覆盖可信输入拒绝、服务未停止拒绝、独占锁冲突、源/目标当前校验、完整资源保护、原子切换、关键阶段中断、坏备份拒绝、启动失败恢复以及启动后新写入保护。root/实际服务 UID 的权限边界须通过真实子进程验证。

使用实际当前产品执行初始化、只读校验、升级及恢复后的业务就绪路径，并核验原有账户、会话、业务记录和文件；不存在未来正式产品版本时只能声明实际演练的同契约切换机制，不能伪造未来发布或数据转换证据。

升级说明、产品支持声明、操作示例、失败恢复流程及实际验收结果全部保存在本仓库。不可变旧 tag 与已封存制品保留原字节，不能覆盖旧发行；历史测试只记录原事实，不计入当前支持。当前实际验证见 [validation.md](validation.md)。
